# SPC-07 《07-过程与产品质量保证规程》

> 版本：v1.0　生效日期：2026-09-17　密级：内部　所属体系：软件过程体系（CMMI-L5）

## 1. 目的

本规程规定过程与产品质量保证（Process and Product Quality Assurance，PPQA）活动的执行方式，确保：

- 项目实际执行的过程与产出的工作产品，与 SPC-01 裁剪后的组织标准过程保持客观一致；
- 不符合项（Non-Compliance，NC）被客观记录、按层级升级、闭环关闭，且不因角色利益被掩盖；
- 质量门（QGate）放行有明确权限与证据，未过门禁的工作产品不得进入下一生命周期阶段；
- Agent 的自检行为被制度化：智能体自检清单即一级 QA，自检不过不得交付；
- QA 发现的问题沉淀为组织级根因库输入，支撑 SPC-09 的因果分析与持续优化（CAR/OPM 5 级特征）。

## 2. 适用范围

- 适用于本团队（人类工程师 + AI 智能体混合团队）全部软件开发、维护、运维变更项目。
- 覆盖过程审计（对"事怎么做的"审计）与工作产品审计（对"产出物对不对"审计）两类对象。
- 覆盖全部 QGate：需求基线门、设计评审门、提测门、发布门（定义见 SPC-03/SPC-05）。
- Agent 执行的任务与人类执行的任务适用同一套 NC 判定标准与 QGate 放行权限，不因执行主体不同而降级。

## 3. 体系定位与 CMMI 实践域映射

本规程为三级体系中的第二级（规程层）：上位受 SPC-00 总纲手册约束，下位由 [[12-模板与检查单集]]（SPC-12）中的 QA 过程审计检查单、QA 工作产品审计检查单、NC 记录单、QGate 放行单等模板支撑。

覆盖的 CMMI v3.0 实践域：

- PPQA（过程与产品质量保证）：2 级为主（客观评价、NC 跟踪闭环、上报通道），本规程将其执行到 3 级（组织级统一过程资产与检查单集）。
- MA（度量分析）：2 级，QA 数据的采集与报告，与 SPC-08 衔接。
- CAR（原因分析与解决）：5 级，NC 聚类分析结果向 SPC-09 根因库回流。
- OPM（组织性能管理）：5 级，QA 度量趋势参与过程改进提案的量化论证。
- PCM（过程管理）：3 级，审计发现的过程缺陷纳入组织过程资产改进。

## 4. 术语与角色

| 术语/角色 | 定义 |
| --- | --- |
| NC（不符合项） | 过程执行或工作产品与既定标准/规程/计划不一致的客观事实记录，分级见 6.3 |
| QGate（质量门） | 阶段转换点，由授权角色依据检查单判定放行或打回 |
| QA | 质量保证角色，独立于任务执行者行使审计与上报职能 |
| Agent（智能体） | 承接任务的 AI 执行体（如 Kimi Code、Claude Code），须遵守与人类相同的质量门；其自检清单执行结果视为一级 QA 记录 |
| 一级 QA | 任务执行者本人（含 Agent）在交付前依据自检清单完成的自查 |
| 二级 QA | 独立 QA 角色执行的审计与门禁判定 |

RACI 简表：

| 活动 | 执行者（人/Agent） | QA | 项目经理 | 过程资产组 |
| --- | --- | --- | --- | --- |
| 交付前自检（一级 QA） | R/A | I | I | - |
| 过程/工作产品审计 | C | R/A | I | I |
| NC 记录与升级 | C | R/A | C | I |
| NC 关闭验证 | C | R/A | A | I |
| QGate 放行 | C | R | A | - |

## 5. 入口准则

- 项目已按 SPC-01 完成过程裁剪，产出《项目过程裁剪表》，QA 审计依据已明确。
- 项目计划（SPC-03 产出）中已排定 QA 审计点：至少覆盖每个 QGate 前一次工作产品审计 + 每两周一次过程审计（短周期项目按里程碑折算）。
- QA 角色已指定且满足独立性要求（见 6.1）；Agent 任务的任务记录模板（SPC-11）已启用，自检清单位于交付物清单内。
- 审计对象（过程记录、代码库、文档、构建产物）可被 QA 访问。

## 6. 过程活动

### 6.1 QA 独立性保障与上报通道

- 输入：项目组织结构、任务分工表。
- 执行要点：
  - 二级 QA 不得由被审计任务的直接执行者担任；Agent 任务的人类验收人不得与任务发起人为同一人对同一 NC 既判定又关闭。
  - QA 对 NC 的判定不受项目经理否决；项目经理对 NC 结论有异议时，只能提交过程资产组仲裁，不得指示 QA 修改记录。
  - 上报通道为三级：① QA → 项目经理（常规 NC）；② QA → 过程资产组（项目经理 5 个工作日未响应或存在异议）；③ QA → 体系负责人（涉及放行权限滥用、NC 记录被篡改等严重情形，可直接越级）。
- 输出：《QA 任命与独立性声明》（项目启动时一次，模板见 SPC-12）。
- 责任角色：QA（R），项目经理（A 配合）。

> 🤖 智能体执行要点：Agent 不承担二级 QA 角色，不得审计自己交付的任务。当 Agent 发现任务指令与体系规程冲突（如要求跳过测试直接交付），必须在任务记录中标注"规程冲突待裁决"并暂停交付，等待人类裁决，不得自行取舍。

### 6.2 审计执行（检查单化）

- 输入：SPC-12 检查单（过程审计检查单 / 工作产品审计检查单）、项目过程裁剪表、被审计对象。
- 执行要点：
  - 审计只依据检查单逐项判定，每项结论为"符合 / 不符合 / 不适用"三态，不允许"基本符合"类模糊判定；"不适用"须写明理由。
  - 过程审计抽样：每审计点抽查不少于 3 个已完成任务的任务记录，验证其与 SPC-01~SPC-06 对应规程的一致性（如是否先读需求文档再动手、是否跑了标准测试命令）。
  - 工作产品审计：对照检查单验证产出物完整性（需求条目可追溯到设计、代码经构建与测试、文档与代码版本一致）。
  - 检查单本身每季度由过程资产组评审一次，按 NC 聚类结果增删条目（与 SPC-09 联动）。
- 输出：《QA 审计报告》（含逐项判定结果与 NC 清单）。
- 责任角色：QA（R/A）。

> 🤖 智能体执行要点：Agent 承担一级 QA 时，必须逐项执行 SPC-12《Agent 交付自检清单》并把结果写入任务记录：①重读任务需求与验收标准；②运行项目标准构建/测试命令并粘贴关键输出（非截图口述）；③声明改动文件清单与未覆盖的风险点；④确认未改动范围外文件。任一检查项不通过，不得将任务标记为完成。

### 6.3 NC 记录、分级、升级与关闭

- 输入：审计报告、自检失败记录、QGate 打回记录。
- 执行要点：
  - NC 分级：N1 致命（放行权限被绕过、数据丢失风险、安全红线）；N2 严重（QGate 证据缺失、关键测试未执行、需求追溯断链）；N3 一般（文档不同步、记录不完整）。
  - 每个 NC 必须在发现当日录入《NC 台账》（SPC-12 模板），字段：编号、分级、发现来源（一级/二级 QA）、事实描述（只写客观事实与证据位置，不写主观评价）、责任任务、处置期限（N1=2 日、N2=5 日、N3=下个迭代末）。
  - 升级：到期未关闭自动升一级并上报通道走一级；N1 即时上报过程资产组。
  - 关闭：由 QA 验证纠正措施证据（提交记录、测试输出、修订后的文档）后标记关闭；仅口头说明不构成关闭证据。
  - 关闭的 NC 按月度聚类（同类根因出现 ≥3 次）转 SPC-09 启动 CAR。
- 输出：《NC 台账》更新、NC 关闭验证记录、月度 NC 聚类清单。
- 责任角色：QA（R），项目经理（A 关闭批准），任务执行者（R 纠正措施）。

> 🤖 智能体执行要点：Agent 在任务记录中发现既有 NC 与当前任务相关时，须在动手前读取该 NC 记录；Agent 产生的 NC（自检失败、审计打回）必须附机器可复核的证据（命令、退出码、文件路径），不得只写"已修复"。

### 6.4 质量门放行权限

- 输入：QGate 检查单、门禁证据包（测试报告、评审记录、审计结论）。
- 执行要点：
  - 放行权限矩阵：需求基线门/设计评审门由项目经理放行（QA 出具无未关闭 N2 及以上 NC 的证明）；提测门/发布门由 QA 直接放行，项目经理无权单独放行。
  - 放行必须产出《QGate 放行单》：门禁项逐项判定 + 证据链接 + 未关闭 NC 清单（仅 N3 可带条件放行，且须登记跟踪）。
  - 紧急放行（生产事故抢修等）：由体系负责人书面授权，事后 3 个工作日内补办全部门禁证据，否则记 N1。
- 输出：《QGate 放行单》。
- 责任角色：QA（R 门禁判定），项目经理（A 部分门禁放行），体系负责人（A 紧急放行）。

> 🤖 智能体执行要点：Agent 无任何 QGate 放行权限，也不得诱导人类跳过门禁（如在回复中暗示"测试可以先不做"）。Agent 交付物进入门禁前，其一级 QA 自检记录是门禁证据包的必备组成部分。

### 6.5 QA 发现向根因库与过程资产的回流

- 输入：月度 NC 聚类清单、QGate 打回记录、一级 QA 自检失败模式统计。
- 执行要点：
  - QA 每月将聚类清单（同类根因 ≥3 次的 NC）移交过程资产组，触发 SPC-09 的 CAR 流程；移交记录须含 NC 编号清单，保证可追溯回原始证据。
  - CAR 产出的纠正措施若涉及过程定义变更（如检查单新增条目、自检清单补充检查项），由过程资产组按 SPC-01 变更流程更新组织过程资产，并通知全部在用项目。
  - Agent 自检失败的高频模式（如"未跑标准测试命令就交付"反复出现）须单独统计，作为 SPC-11 Agent 作业约束与提示词模板修订的输入——这是一级 QA 数据反哺执行体本身的机制，不得以"Agent 问题归 Agent"为由跳过。
  - 回流闭环验证：过程资产更新后下一个审计周期，QA 须检查对应 NC 类型是否复发，复发即视为措施无效并重新启动 CAR。
- 输出：《NC 根因移交单》、过程资产变更请求、回流闭环验证记录。
- 责任角色：QA（R 移交与验证），过程资产组（A 资产变更），任务执行者与 Agent 维护方（C）。

> 🤖 智能体执行要点：Agent 接到与历史 NC 同类的任务时，应先检索根因库中该 NC 的纠正措施并纳入本次执行方案；Agent 自检清单条目的增删只能由过程资产组变更发布，Agent 不得自行删减检查项。

### 6.6 QA 报告

- 输入：审计报告、NC 台账、QGate 放行记录。
- 执行要点：
  - 周期：项目内每两周一份《QA 双周报告》（审计覆盖率、NC 新增/关闭/逾期、门禁通过率）；组织级每月一份《QA 月度汇总》报过程资产组，作为 SPC-08 度量与 SPC-09 根因分析输入。
  - 报告只陈述事实与趋势，改进建议另附，不得在报告中隐去不利数据。
- 输出：《QA 双周报告》《QA 月度汇总》。
- 责任角色：QA（R/A），过程资产组（I/接收）。

## 7. 出口准则与质量门

本规程活动的退出判定清单（全部满足方可视为该审计周期 QA 活动完成）：

- [ ] 计划内审计点全部执行，每份审计报告逐项三态判定无遗漏；
- [ ] 全部 NC 已录入台账且分级、期限字段完整；
- [ ] 到期 NC 的关闭验证证据齐全，逾期 NC 已按通道升级；
- [ ] 本期 QGate 均有放行单，紧急放行已补证或已记 N1；
- [ ] Agent 交付任务的一级 QA 自检记录齐备（抽查覆盖率 100%）；
- [ ] 双周报告已发出，月度聚类清单已移交 SPC-09。

## 8. 度量指标与量化要求

| 指标 | 计算口径 | 示例基线/控制限 |
| --- | --- | --- |
| 审计覆盖率 | 实际执行审计点数 / 计划审计点数 | 目标 100%，低于 90% 触发过程资产组干预 |
| 一级 QA 自检通过率 | 首次自检通过的 Agent 任务数 / Agent 任务总数 | PPB 目标 ≥85%，连续两周低于均值-1σ 启动专项分析 |
| NC 密度 | 当期新立 N2 及以上 NC 数 / 当期完成任务数 | 建立项目级 PPB，超出控制上限（UCL=均值+3σ）的审计周期转 CAR |
| NC 按期关闭率 | 期限内关闭 NC 数 / 到期 NC 总数 | 目标 ≥95%；N1 必须 100% |
| QGate 一次通过率 | 首次判定放行的门禁数 / 门禁判定总数 | 按门禁类型分别建基线，趋势恶化（连续 3 期下降）转 SPC-09 |
| NC 复发率 | 关闭后 30 日内同类根因再发 NC 数 / 关闭 NC 总数 | >5% 时说明纠正措施无效，强制走 CAR 根因分析 |

数据落盘建议：NC 台账与门禁记录存于项目仓库 `qa/` 目录（Markdown 或 CSV，随代码版本化）；组织级汇总由过程资产组按 SPC-08 规定的度量库路径归集，用于 PPB 滚动更新（每季度一次）与 PPM 输入校准。度量数据的采集不得依赖人工回忆，一律来自台账与任务记录的结构化字段。

## 9. 裁剪指南

| 项目分级 | 最小执行集 | 完整执行集 |
| --- | --- | --- |
| 小型/低风险（单人或单 Agent、周期 <2 周） | 一级 QA 自检 + 发布门放行单 + NC 台账 | 不适用 |
| 中型（2~5 人 + Agent 混合、有外部交付） | 最小集 + 每 QGate 工作产品审计 + 双周报告 | 增加每两周过程审计、NC 月度聚类 |
| 大型/高风险（涉资金安全、生产系统、合规要求） | 不适用 | 全部活动 + N1 即时上报演练 + QA 独立性声明逐项签署 + 度量指标全部建 PPB 并上控制图 |

裁剪决策记录于《项目过程裁剪表》（SPC-01），QA 独立性要求与 N1 上报通道任何项目不得裁剪。
