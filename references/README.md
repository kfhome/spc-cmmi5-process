# SPC-00 《软件过程体系总纲手册》（对标 CMMI v3.0 成熟度 5 级）

> 版本：v1.0　生效日期：2026-09-17　密级：内部　所属体系：软件过程体系（CMMI-L5）
> 本手册是体系的最高层文件；任何规程与本手册冲突时，以本手册为准并发起规程修订。

## 1. 目的

建立一套对标软件能力成熟度模型（CMMI v3.0）**成熟度 5 级——优化级**的软件过程体系文件，使本组织（人 + AI 智能体混合团队）的软件开发达到：

1. **已管理**（2 级）：每个任务有需求、有计划、有跟踪、有验证；
2. **已定义**（3 级）：所有项目从组织标准过程集（OSSP）裁剪而来，过程资产持续积累；
3. **量化管理**（4 级）：关键子过程以过程性能基线（PPB）与控制图进行统计管理，用过程性能模型（PPM）做预测；
4. **持续优化**（5 级）：缺陷与偏差走根因分析（CAR）闭环，改进提案经成本收益分析与试点验证后回流过程资产。

## 2. 适用范围

- 本知识库管辖的全部软件开发、脚本工具、课件工程、部署运维类任务；
- 所有任务执行者：人类工程师，以及 Kimi Code、Claude Code 等各类 AI 智能体（Agent）。**Agent 与人类遵守同一套质量门**，差异仅在放行权限（见 SPC-07）。

## 5. 智能体（Agent）使用本体系的强制路径

任何 Agent 接到开发任务时，按以下顺序工作（细则见 SPC-11）：

1. **定位需求**：确认任务对应的需求条目与验收标准（SPC-02）；歧义走升级路径，不猜。
2. **查裁剪**：按任务规模/风险确定最小执行集（各规程第 9 节）。
3. **计划先行**：非平凡任务先出计划/方案；技术选型与架构改动先报方案获确认（SPC-10）。
4. **照章执行**：遵守 SPC-04 编码与集成要求、SPC-06 备份与变更纪律。
5. **验证交付**：交付前运行项目标准构建/测试命令并留存证据（SPC-05），过自检清单（SPC-07）。
6. **留痕度量**：任务结束按统一格式记录工时/缺陷/返工（SPC-08）。
7. **沉淀改进**：踩坑与经验按 SPC-09 回流为体系条目或规则更新。

## 6. 维护规则

- 本体系文件自身是受控配置项（CI），变更走 SPC-06 变更流程：修订对应规程并在其第 11 节"变更记录"追加一行；
- 新增/废止规程须同步修订本手册第 3 节清单与知识库 `AGENTS.md`（追加式条目）；
- 过程改进（含 Agent 实践中验证有效的做法）经 SPC-09 试点验证后，由过程资产组写入相应规程；
- 年度评审：每年对全套规程做一次适用性评审，结合 SPC-08 度量数据决定 PPB 刷新与规程修订。
